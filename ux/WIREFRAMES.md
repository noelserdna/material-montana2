Reglas comunes a todas las pantallas:

- Los textos entre «comillas» son **literales** de los criterios de aceptación o de VO-010 y no se reformulan (REQ-C-001). Los textos `UX-TXT-nn` son etiquetas/ayudas propias del diseño (catálogo al final).
- **No hay pantalla de registro ni de recuperar contraseña** (RN-001): las cuentas las prepara el encargado.
- Cada pantalla tiene una zona fija de mensajes (`mol-form-feedback`) donde aparecen los literales de éxito/error, para que el criterio «el usuario ve X en {pantalla}» se cumpla siempre en esa pantalla.
- Las listas se cargan al abrir la pantalla y tras cada acción (datos compartidos, REQ-NF-001); mientras cargan muestran «Cargando…» (`UX-TXT-04`).
- Marcas de los wireframes: `[Botón]`, `[______]` campo, `[v ____]` desplegable, `(o)` / `( )` radio, `[x]` casilla, `{…}` dato variable.

## SCR-001: Iniciar sesión

### Purpose
Entrar con correo y contraseña (UC-001). Única pantalla accesible sin sesión; destino de cualquier dirección privada sin sesión (AC-016-04).

### Entry Conditions
- Abrir la web sin sesión; sesión caducada o cerrada; cualquier dirección privada sin sesión.

### ASCII Wireframe (Desktop)

```

|                                                                  |

|            |  [______________________________]    |              |
|            |  Contraseña (obligatorio)            |              |
|            |  [______________________________]    |              |
|            |  [ ] Mostrar contraseña              |              |
|            |                                      |              |
|            |  [ Entrar ]                          |              |
|            |  (zona de mensajes)                  |              |
|            |  ! Correo o contraseña incorrectos   |              |
|            +--------------------------------------+              |
|            ¿Sin cuenta? Pídela al encargado del material         |
+------------------------------------------------------------------+
```

### ASCII Wireframe (Mobile)

```
+--------------------------+
| Club de Montaña          |
| Iniciar sesión       (h1)|
| Correo (obligatorio)     |
| [______________________] |
| Contraseña (obligatorio) |
| [______________________] |
| [x] Mostrar contraseña   |
| [        Entrar       ]  |
| ! Correo o contraseña    |
|   incorrectos            |
| ¿Sin cuenta? Pídela al   |
| encargado del material   |
+--------------------------+
```

### Layout Description
- **Structure:** `tmpl-centrado`, tarjeta de ancho máx. 24 rem centrada; sin menú (no hay sesión).
- **Sections:** título → formulario (`org-login-form`) → zona de mensajes → pista de alta (`UX-TXT-02`).
- **Primary Action:** «Entrar». **Secondary:** casilla «Mostrar contraseña» (`UX-TXT-05`).

### Component Inventory

| Zone | Component | Type | Props/Variants |
|------|-----------|------|----------------|
| Main | `org-login-form` | organism | 2 × `mol-field` (email, password), `atom-button` primary, `mol-form-feedback` |
| Main | `atom-alert` | atom | error |

### Interactive Elements

| Element | Trigger | Action | Feedback |
|---------|---------|--------|----------|
| Entrar | clic / Intro | envía correo y contraseña; el servidor decide | éxito: se abre la pantalla de aterrizaje del rol con «Hola, {correo}» en la cabecera; fallo: «Correo o contraseña incorrectos» en la zona de mensajes, los campos conservan el correo y vacían la contraseña |
| Reenvío del formulario ya enviado | segundo envío | conserva una sola sesión (AC-001-04) | igual que éxito |
| Mostrar contraseña | casilla | cambia `type` password↔text | solo visual |

### Responsive Adaptations

| Breakpoint | Change |
|-----------|--------|
| < md | tarjeta a ancho completo, sin borde ni sombra; botón a ancho completo |
| < sm | etiquetas encima de campos (igual que desktop); sin cambios adicionales |

### Accessibility Notes
- **Tab Order:** Correo → Contraseña → Mostrar contraseña → Entrar → (enlace ninguno).
- **Landmarks:** `main`; sin `nav`. `h1` = «Iniciar sesión».
- **Focus Management:** al cargar, foco en Correo. Tras un fallo, foco en el mensaje de error (`tabindex="-1"`), no en el campo, para que se anuncie.
- **Screen Reader:** el error es `role="alert"`; los campos llevan `aria-describedby` al error; `autocomplete` correcto y pegar permitido (3.3.8). Sin atributos `required`/`pattern`/`type=email` bloqueantes.

### Related Specs
- UC-001, REQ-F-001, REQ-F-016 (sin sesión → esta pantalla), RN-001, WF-001 (entrada)

## SCR-002: Material

### Purpose
Ver el catálogo (cinco tipos y los que añada el encargado) con su número de unidades y reservar un material para un rango de fechas (UC-003, UC-002). Aquí aparecen los rechazos de reserva: sin unidades libres, multa pendiente, duplicado, fechas invertidas.

### Entry Conditions
- Sesión de socio, encargado o junta. Aterrizaje del socio. La junta lo ve **sin** formulario de reserva (REQ-F-015).

### Layout Description
- **Structure:** dos bloques; ≥ `md` en dos columnas (catálogo | formulario); < `md` apilados (catálogo, luego formulario).
- **Sections:** catálogo (`org-catalogo`) → formulario (`org-reserva-form`) → zona de mensajes bajo el botón.
- **Primary Action:** «Reservar» (envía el formulario). **Secondary:** «Reservar {material}» en cada tarjeta solo rellena el desplegable del formulario y mueve el foco al campo Desde; no reserva por sí mismo (evita reservas sin fechas).

### Component Inventory

| Zone | Component | Type | Props/Variants |
|------|-----------|------|----------------|
| Main-left | `org-catalogo` > `mol-material-card` | organism/molecule | «{material}» + «{n} unidades» (literal REQ-F-003: «1 unidades» se mantiene tal cual) |
| Main-right | `org-reserva-form` | organism | `mol-field` select Material, `mol-date-range`, `atom-button` primary, `mol-form-feedback` |

### Interactive Elements

| Element | Trigger | Action | Feedback |
|---------|---------|--------|----------|
| Reservar (formulario) | clic / Intro | pide una unidad del material para el rango; el servidor valida | éxito: se abre **Mis reservas** con «Reserva creada: {material} del {desde} al {hasta}» (AC-002-01/02/04); errores en la zona de mensajes de **Material**: «No quedan unidades libres de {material} esas fechas», «Ya tienes esa reserva», «La fecha de fin no puede ser anterior a la de inicio», «No puedes reservar hasta pagar tu multa de {importe} €», «Ese material no existe» |
| Reservar {material} (tarjeta) | clic | preselecciona el material | foco en Desde |

Regla UX de aviso por multa: si el servidor responde «No puedes reservar hasta pagar tu multa de {importe} €», el mensaje se mantiene visible (no desaparece solo) y el formulario sigue activo (el socio puede reintentarlo tras pagar); no se bloquea el formulario por adelantado porque la decisión es del servidor (REQ-F-009).

### Responsive Adaptations

| Breakpoint | Change |
|-----------|--------|
| < md | catálogo y formulario apilados; tarjetas a ancho completo; botón del formulario a ancho completo |
| < sm | el botón de cada tarjeta pasa a ocupar una línea propia con nombre accesible «Reservar {material}» |

### Accessibility Notes
- **Tab Order:** cabecera/menú → tarjetas (botón Reservar de cada una) → Material → Desde → Hasta → Reservar.
- **Landmarks:** `banner`, `nav` «Principal», `main`; catálogo como `<ul>` bajo `h2`.
- **Focus Management:** al fallar, foco al mensaje de error; al elegir una tarjeta, foco a Desde; tras éxito la navegación a Mis reservas pone el foco en el `h1` de esa pantalla y su mensaje de éxito se anuncia (`role="status"`).
- **Screen Reader:** el mensaje de error es `role="alert"`; las fechas se anuncian con su etiqueta y el formato `AAAA-MM-DD`; los campos de fecha nunca usan solo selector visual.

### Related Specs
- UC-002, UC-003, UC-009, UC-012 (E5/AC: sin unidades tras baja), REQ-F-002, REQ-F-003, REQ-F-009, REQ-F-015, WF-001 paso 1

## SCR-003: Mis reservas

### Purpose
Lista de las reservas del propio usuario (nunca las de otros) con material, fechas y estado; cancelar hasta el día antes (UC-004, UC-005).

### Entry Conditions
- Tras crear una reserva; desde el menú. Socio o encargado (la junta no reserva, no ve esta sección).

### ASCII Wireframe (Desktop)

```
+------------------------------------------------------------------------------+
| {cabecera común}                                                             |
+------------------------------------------------------------------------------+
| Mis reservas                                                             (h1)|
| (zona de mensajes) Hecho: Reserva creada: Casco del 2026-12-10 al 2026-12-12 |
|                                                                              |
| Material | Desde      | Hasta      | Estado     | Acción                     |
| ---------+------------+------------+------------+--------------------------- |
| Casco    | 2026-12-10 | 2026-12-12 | Reservada  | [Cancelar reserva]         |
| Cuerda   | 2026-12-20 | 2026-12-21 | Cancelada  |                            |
| Piolet   | 2026-11-02 | 2026-11-04 | Devuelta   |                            |
+------------------------------------------------------------------------------+
  Vacío: "Todavía no tienes reservas"   Ver el material >>>
```

### ASCII Wireframe (Mobile)

```
+--------------------------+
| Mis reservas         (h1)|
| Hecho: Reserva creada:   |
| Casco del 2026-12-10 al  |
| 2026-12-12               |
| +----------------------+ |
| | Casco     [Reservada]| |
| | 2026-12-10 → 2026-12-12|
| | [Cancelar reserva]   | |
| +----------------------+ |
| | Cuerda    [Cancelada]| |
| | 2026-12-20 → 2026-12-21|
| +----------------------+ |
+--------------------------+
```

### Layout Description
- **Structure:** tabla semántica ≥ `md`; tarjetas apiladas < `md`. Orden: reservas más próximas primero (`UX-TXT` no necesario: orden por `desde` ascendente; las terminadas al final).
- **Sections:** zona de mensajes → lista (`org-lista-reservas`) o estado vacío.
- **Primary Action:** ninguna global. **Secondary:** «Cancelar reserva» por fila, solo en filas `Reservada`.

### Component Inventory

| Zone | Component | Type | Props/Variants |
|------|-----------|------|----------------|
| Main | `org-lista-reservas` > `mol-reserva-row` | organism/molecule | `atom-badge-estado` (Reservada, Entregada, Devuelta, Cancelada) |
| Main | estado vacío | molecule | «Todavía no tienes reservas» + enlace a Material |

### Interactive Elements

| Element | Trigger | Action | Feedback |
|---------|---------|--------|----------|
| Cancelar reserva | clic | cancela si hoy < inicio (decide el servidor) | éxito: «Reserva cancelada» y la fila pasa a «Cancelada»; hoy = inicio: «Ya no se puede cancelar: la reserva empieza hoy» y la fila sigue «Reservada»; repetir: fila sigue «Cancelada» (`O_ALREADY_CANCELLED`) |

Decisión de diseño: el botón se muestra en toda reserva `Reservada` aunque ya no sea cancelable ese día, **sin deshabilitarlo** (un botón deshabilitado ocultaría el literal «Ya no se puede cancelar: la reserva empieza hoy» que el criterio exige ver); el servidor rechaza y el mensaje explica. Las reservas ajenas nunca se muestran (REQ-F-004, REQ-F-016).

### Responsive Adaptations

| Breakpoint | Change |
|-----------|--------|
| < md | tabla → tarjetas; botón a ancho completo dentro de la tarjeta |
| < sm | fechas en una sola línea «desde → hasta» con texto visible de «Desde»/«Hasta» para lectores (`aria-label`) |

### Accessibility Notes
- **Tab Order:** menú → botones «Cancelar reserva» por fila en orden visual.
- **Landmarks:** `main`; la tabla con `<caption>` «Mis reservas» (oculto visualmente) y `<th scope="col">`.
- **Focus Management:** tras cancelar, el foco vuelve al botón de la siguiente fila (o al mensaje si no queda ninguna); si la fila desaparece no se pierde el foco al `body`.
- **Screen Reader:** el nombre del botón incluye material y fecha: «Cancelar reserva de Casco del 2026-12-10»; el mensaje de resultado es `role="status"` (éxito) o `role="alert"` (error).

### Related Specs
- UC-004, UC-005, REQ-F-004, REQ-F-005, WF-001 (Cancelada)

## SCR-004: Entregas y devoluciones

### Purpose
El encargado entrega lo reservado y marca devoluciones con su fecha real (UC-006, UC-007). Es el sitio donde ve las reservas de todos los socios (REQ-NF-001, AC-NF-001).

### Entry Conditions
- Sesión del encargado. Un socio o la junta que llegue aquí ve SCR-009.

| Material | Socio            | Desde      | Hasta      | Estado    | Acción    |
| ---------+------------------+------------+------------+-----------+---------- |
| Casco    | lucia@club.es    | 2026-12-10 | 2026-12-12 | Reservada | [Entregar]|
| Cuerda   | pablo@club.es    | 2026-12-20 | 2026-12-21 | Entregada | Devuelta el:|
|          |                  |            |            |           | [2026-12-21]|
|          |                  |            |            |           | [Devolver]|
+------------------------------------------------------------------------------+
```

### ASCII Wireframe (Mobile)

```
+--------------------------+
| Entregas y devoluciones  |
| Ver: (o)Por entregar     |
|      ( )Entregadas ( )Todas|
| Hecho: Devuelta el       |

| | Casco · lucia@club.es| |

### Layout Description
- **Structure:** filtro por estado + lista. Cada fila ofrece **una sola acción** según su estado: `Reservada` → «Entregar»; `Entregada` → fecha «Devuelta el» (por defecto hoy) + «Devolver»; `Devuelta`/`Cancelada` → sin acción.
- **Primary Action:** la de cada fila.
- **Aviso de falta de material (RN-002):** sobre la lista, si algún día de una reserva `Reservada` o `Entregada` supera las unidades activas del material, bloque `atom-alert` de aviso `UX-TXT-07` con el material, el día y los socios afectados, para que el encargado avise por su cuenta. Se calcula en el cliente con las unidades activas (Inventario) y las reservas ya listadas; no hay envío automático ni correo.

### Component Inventory

| Zone | Component | Type | Props/Variants |
|------|-----------|------|----------------|
| Top | `atom-alert` aviso (falta material) | atom | warning, condicional |
| Main | `org-lista-entregas` > `mol-entrega-row` | organism/molecule | estados Reservada/Entregada/Devuelta/Cancelada |

### Interactive Elements

| Element | Trigger | Action | Feedback |
|---------|---------|--------|----------|
| Entregar | clic | marca entregada | «Entregada a {correo}»; repetir: «Ya estaba entregada»; cancelada: «No se puede entregar una reserva cancelada» |
| Devolver (con fecha) | clic | registra la devolución en la fecha indicada | sin retraso: «Devuelta el {fecha} sin retraso»; con retraso: «Multa de {importe} € por {dias} días de retraso» (se ve también en Multas); no entregada: «Solo se puede devolver lo que se ha entregado»; repetir: «Ya estaba devuelta» |

La fecha de devolución es editable (el encargado puede registrar el día real si no coincide con hoy); si queda vacía o inválida el servidor responde y su literal se muestra (sin `required` bloqueante).

### Responsive Adaptations

| Breakpoint | Change |
|-----------|--------|
| < md | tabla → tarjetas; la fecha y «Devolver» apilados a ancho completo |
| < sm | filtro en pila vertical |

### Accessibility Notes
- **Tab Order:** filtro → (aviso) → por fila: fecha (si hay) → botón de acción.
- **Landmarks:** `main`; filtro como `<fieldset><legend>Ver</legend>`.
- **Focus Management:** tras una acción correcta el foco va al mensaje de resultado; la lista se recarga sin perder la posición.
- **Screen Reader:** nombre del botón: «Entregar Casco a lucia@club.es», «Devolver Cuerda de pablo@club.es»; mensajes `role="status"`/`alert`; el aviso de falta de material `role="status"` (no interrumpe).

### Related Specs
- UC-006, UC-007, UC-008, REQ-F-006, REQ-F-007, REQ-NF-001, RN-002, WF-001 pasos 2–3

## SCR-009: Sin permiso (estado de error)

### Purpose
Respuesta a una dirección o acción que el rol no puede usar (UC-013 E1, UC-014 E1, REQ-F-016). No muestra ningún dato.

### Entry Conditions
- Un socio abre la dirección del historial de otro socio; un socio o la junta abre una pantalla del encargado.

### ASCII Wireframe (Desktop y Mobile)

```
+------------------------------------+
| {cabecera común, menú de su rol}   |
| ! No tienes permiso para ver       |
|   estos datos                      |
| [Volver a {pantalla de aterrizaje}]|
+------------------------------------+
```

### Layout Description
- Texto: «No tienes permiso para ver estos datos» (lectura) o «No tienes permiso para hacer esto» (acción); enlace «Volver» (`UX-TXT-13`) a la pantalla de aterrizaje del rol. No distingue «no existe» de «no es tuyo» (AUTHZ-002).

### Accessibility Notes
- **Focus Management:** el foco entra en el mensaje (`role="alert"`, `tabindex="-1"`). **Landmarks:** `main`, el título `h1` es el propio mensaje.

### Related Specs
- UC-014, UC-013, REQ-F-016, AUTHZ-002
