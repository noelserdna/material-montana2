# ADR Draft 001: SPA Vite + API Node en un monolito modular

> **Status:** Proposed — generated by `/sdd-tech-designer`, pending review (aprobarlo es decisión de una persona)
> **Date:** 2026-11-16
> **Dimension:** 2 Architecture Style (y 1, 3)

## Context

REQ-C-002 fija JavaScript + Vite + Vitest. REQ-NF-001 exige datos compartidos entre sesiones y dispositivos, así que un navegador solo no basta: hace falta lógica y almacén en servidor. 4 módulos de contrato (API-001..004), un club, un equipo. Contratos `Style: operations`.

## Decision

Un único proyecto: SPA vanilla en `src/ui`, API Node en `src/server` montada como middleware de Vite en desarrollo (`npx vite --host 127.0.0.1 --port 5173`) y como proceso Node en producción, dominio puro en `src/domain`. Transporte `POST /api/<operación>` JSON.

## Alternatives Considered

| Alternative | Pros | Cons | Fit Score (1-5) |
|------------|------|------|-----------------|
| Monolito modular, API como plugin de Vite (seleccionada) | un comando, un puerto, respeta el perfil | acopla API al ciclo de Vite en dev | 5 |
| Dos procesos (Vite SPA + servidor aparte) | separación nítida | dos arranques, CORS, perfil con un solo `server` | 3 |
| Microservicios / serverless | escala | sobredimensionado | 1 |

## Consequences

### Positive

- Arranque y E2E sencillos; dominio probado sin navegador.

### Negative

- Una sola instancia; sin escalado horizontal.

### Risks

- La API vive en el servidor de desarrollo de Vite: mitigado con `src/server/main.js` para producción que reutiliza los mismos manejadores.
